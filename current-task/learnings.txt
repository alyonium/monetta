# Learnings

- i18n: `src/i18n/en.ts` nested catalog, init in `src/i18n/index.ts`, typed keys via `src/i18n/i18next.d.ts`. One namespace `translation`. Components use `useTranslation()` and full keys (`t('budget.income')`), same as login. Interpolation: `{{name}}`.
- Tests: `npm test` runs `vitest run`. Config is `vitest.config.ts` (`environment: 'node'`, alias `@` → `src`). Do not put tests in `vite.config.ts` (PWA plugin). Shared `localStorage` stub: `src/helpers/tests/stubLocalStorage.ts` (not a `*.test.ts`, so Vitest does not run it). Budget helper tests live in `src/modules/budget/helpers/tests/` (SDK fixtures in `testHelpers.ts`, not `helpers.ts`). Tests that are not helpers sit next to the source (`components/accountIcons.test.ts`). Do not put a `tests/` folder at the module root. Phosphor catalog is UI: `components/accountIcons.ts`; helpers must not import Phosphor.
- Typecheck: `tsconfig.app.json` maps `@/*` via `paths` to `./src/*`. Do not add `baseUrl`.
- Firefly client: do not edit `src/api`. Configure the singleton from `src/helpers/configureApiClient.ts`. Storage keys: `monetta.token`, `monetta.backendUrl`. `normalizeBackendUrl` trims, takes origin, returns `{origin}/api` (`/v1` is added by the SDK). Normalize on write (`setBackendUrl`) and again in `configureApiClient` before `baseUrl`. `setConfig` merges; pass `null` header values to delete. Stub `localStorage` in tests via `vi.stubGlobal`.
- Login: `src/modules/login/Login.tsx` + `Login.module.css`. Route is `ROUTE.LOGIN` (`/monetta/login`). Check credentials with `getCurrentUser`, not `getAbout`. `throwOnError` stays false; try/catch treats HTML/JSON parse and network/CORS as `invalidBackendUrl`. 401/403 → `invalidToken`. Write `localStorage` only after success. Helper tests in `src/modules/login/helpers/tests/`; mock `getCurrentUser` from `@/api/sdk.gen.ts`. Logout/clear is US-039.
- Auth shell: `hasAuthCredentials()` in `src/helpers/authStorage.ts` (both keys non-empty after trim). `RequireAuth` lives in `src/components/RequireAuth/`. `AppLayout` is a `100dvh` column + footer in `src/components/AppLayout/` (`AppLayout.tsx` + `AppLayout.module.css`, tabs in `constants.ts`). Routes: `ROUTE.HISTORY` / `ANALYTICS` / `SETTINGS`. Login is outside the layout and does not redirect away if already signed in. Query persist wraps the authenticated tree (`RequireAuth` → `QueryPersistenceProvider` → `AppLayout`). Budget chrome (US-009) fills `AppLayout` `main`. Shared UI in `src/components/<Name>/` follows the same layout as a module (component + CSS together, `constants`/`helpers`/`hooks`/`types`/`tests` only when needed).
- Query persist: `@tanstack/react-query` + `@tanstack/react-query-persist-client` + `idb-keyval`. Query helpers live in `src/helpers/query/` (`constants.ts`, `createQueryClient.ts`, `createQueryPersister.ts`). Provider is a route layout (`QueryPersistenceProvider` + `Outlet`) under `RequireAuth`, not around `App`. Login stays outside Query. Client via `useState(createQueryClient)`. Storage key `monetta.queryCache`. `gcTime` is `Infinity` (do not use 90d: `setTimeout` overflows at ~24.8d and GC's the restore in 1ms). Persist `maxAge` is 90 days. `staleTime` is 1 hour; `retry` is 1. `onSuccess` restore calls `invalidateQueries()` so a cold start refetches Firefly. Logout should call `queryClient.clear()` plus `removeClient()` (US-039). Do not add Query to `openapi-ts` / `src/api`.
- Wallet currency: helpers in `src/helpers/currency/` (`types.ts`, `fetchPrimaryCurrency.ts`, `fetchExchangeRates.ts`, `convertToPrimary.ts`, `formatWalletAmount.ts`). Query keys `PRIMARY_CURRENCY_QUERY_KEY` / `EXCHANGE_RATES_QUERY_KEY`. Fetcher tests in `src/helpers/currency/tests/`; other shared helpers stay in `src/helpers/tests/`. Use `getPrimaryCurrency`, not `primaryCurrency` (that POST makes a currency primary). `listCurrencyExchangeRates` is paged (`limit` 50); keep latest `date` per `from+to` and uppercase codes. Empty rates is valid. `convertToPrimary` is pure: same code → amount; direct `from→primary`; else reverse `1/rate`; no pair → `null` (no 1:1, no third currency, no rounding). `formatWalletAmount` uses `toFixed(decimalPlaces)` for parameters-bar / Analytics totals. Account cards stay on `formatAccountAmount` without rounding.
- Budget constants: `src/modules/budget/constants/` (`account.ts`, `appearance.ts`, `queries.ts`, `layout.ts`, `transactions.ts`). No barrel `constants.ts` — a file and a folder would clash with `.ts` imports. Import the specific file.
- Budget accounts: types in `src/modules/budget/types/budgetAccount.ts` (`AccountType` INCOME|CURRENT|EXPENSE, `isDebt`, currency, debt fields). `icon`/`color` are `string | null` — no Wallet/`#4C6EF5` in the model; UI fallback is US-010/US-016. Map Firefly with `Pick<AccountRead, 'id' | 'attributes'>`: revenue→INCOME, asset→CURRENT, expense→EXPENSE, liability/liabilities→EXPENSE+debt; skip `active: false`, empty id/name, other Firefly types. Buckets keyed by `AccountType`; order preference wire key is `type.toLowerCase()` (`monetta.accountOrder.income`). Preferences: paged `listPreference`, PUT `updatePreference`, and POST `storePreference` when PUT returns 404 (this Firefly does not create missing keys on PUT). Appearance is a JSON string; `PolymorphicProperty` is not an object. Do not write appearance while mapping. This instance also has old `moneta.*` / `monetra.*` keys; the app reads only `monetta.` and `parseOrder` needs a string array.
- Firefly paging: `collectFireflyPages` in `src/helpers/collectFireflyPages.ts`. Tests in `src/helpers/tests/`. `page` from 1; caller sets `limit` inside `fetchPage`. Missing payload/`data` throws `missingError`; empty `data: []` is valid. Non-Error SDK throws become `Error(missingError)`. Used by `fetchAccountPreferences`, `fetchExchangeRates`, `fetchBudgetAccounts`. Keep `PREFERENCES_PAGE_LIMIT`, `EXCHANGE_RATES_PAGE_LIMIT`, and `ACCOUNTS_PAGE_LIMIT` as separate 50s.
- Budget query: `useBudgetAccounts(month)` is a thin `useQuery` over `fetchBudgetAccounts(date)`. Prefix `BUDGET_ACCOUNTS_QUERY_KEY` is `['budget', 'accounts']`; the live key is `['budget', 'accounts', date]` so `invalidateQueries` still matches. `date` is `fireflyBalanceDate`: current month → today, past month → last day, future → today. Still do not pass `type` to `listAccount`. Do not remap `BudgetAccountsByBlock` to `income`/`current`/`expense` and do not default `data` with empty arrays — `data === undefined` means no cache yet. Budget keeps `ParametersBar` when `!data`; loading/error status replaces the account blocks only. `emptyAccountsByType` stays private in `toBudgetAccounts`. No `placeholderData`/`initialData`. `invalidateQueries` after mutations is US-017+. Live cache→refetch needs a Firefly PAT.
- Budget chrome: `Budget.tsx` + `Budget.module.css` fill `AppLayout` `main` (`height: 100%`, column, `overflow: hidden`). `AppLayout` `main` is `overflow: hidden` so pages own scroll (History/Analytics add theirs later). `ParametersBar` has `MonthPickerInput` (`month` + `onMonthChange`; `maxDate` today; `valueFormat` `MMM YYYY`; ignore `null`) and read-only Income/Expenses/Balance via `useBudgetMonthTotals`. Edit is still a stub (US-027). Month state lives in `Budget` (`useState`, not localStorage). `AccountBlock` is pager only, no visible heading (`aria-label` via `budget.income` / `budget.current` / `budget.expense`). Income/Current `flex-shrink: 0`; Expense `flex: 1` so it takes leftover space above the footer. Page gap between blocks is `16px`. Bar labels: `budget.parameters.*` (`expenses` vs block `budget.expense`). Do not duplicate the footer.
- Budget month: helpers in `helpers/budgetMonth.ts`. Clock is only `todayIso()`. Formulas take `MonthToday` (`startOfMonth`, `fireflyBalanceDate`, `monthRange`, `defaultTransactionDate`). React files do not import dayjs. `@mantine/dates/styles.css` is imported in `App.tsx` right after core styles. Mantine 9 values are `YYYY-MM-DD` strings. `defaultTransactionDate` is for US-024 (today if current Budget month, else first of month) — do not wire it into transaction UI yet. `monthRange` is `{ start: startOfMonth, end: fireflyBalanceDate }` for insight totals.
- Budget month totals: Income/Expenses from `insightIncomeTotal` / `insightExpenseTotal` (`result.data` is a raw `InsightTotal` array, not JSON:API). `accounts[]` omitted. `Math.abs` on insight `difference` (Firefly may send expenses negative). Balance is the sum of Current (asset) `balance` on `fireflyBalanceDate`, not Income − Expenses and not `getBasicSummary`. Convert each currency with `convertToPrimary`; missing rate → `null` → `'—'` (no partial sum). Empty insights/Current → `0.00`. Query keys: `['budget', 'insights', start, end]`, plus shared currency keys. `useBudgetMonthTotals` reuses `useBudgetAccounts` cache. Mutations later should also invalidate `BUDGET_INSIGHTS_QUERY_KEY`. Do not use Firefly `pc_current_balance`.
- Budget cards: `AccountItem` + `AddAccountButton`. UI fallbacks `DEFAULT_ACCOUNT_ICON` (`Wallet`) and `DEFAULT_ACCOUNT_COLOR` (`#4C6EF5`) — do not bake them into the mapper. Account icons are a closed catalog in `components/accountIcons.ts` (`ACCOUNT_ICONS` + `resolveAccountIcon`); preference key is the catalog name (`Wallet`), not `WalletIcon`. Unknown/missing names fall back to Wallet. Helpers must not import Phosphor. Picker iterates `ACCOUNT_ICONS` (50 Phosphor names, named imports only). `AccountIcon` is a static wrapper (icon as prop) for `static-components`. One `AccountPageGrid` for all blocks; height via `--account-card-min-height` (`ACCOUNT_CARD_MIN_HEIGHT_DEFAULT` 6rem, Expense `ACCOUNT_CARD_MIN_HEIGHT_EXPENSE` 7.5rem) so cards and Add match. Add takes `onClick` (US-016). Debt: `debtAmount` red, `paidAmount` green, no `balance`. `formatAccountAmount` is number + symbol (else code), no `convertToPrimary`. `budget.addAccount` i18n. Cards are not buttons (US-018).
- Account icon picker: `AccountIconPicker` in `src/modules/budget/components/AccountIconPicker/` (Budget-only, not `src/components`). Controlled: `opened` + `onClose` + `value: AccountIconName` + `onChange` (commit only on cell click) + required `color` (CSS `--account-icon-picker-color` / `--account-icon-picker-glyph-color` for selected glyph/border/fill). Overlay/Escape call `onClose` only and must not close Create. Modal content is height-capped with `overflow: auto` on the body so the grid scrolls. Catalog guard is `isAccountIconName` / `toAccountIconName` (trim + Wallet fallback); `resolveAccountIcon` is `ACCOUNT_ICONS[toAccountIconName(name)]`. Grid glyphs use a static `IconCell` (`icon` prop, `aria-label={name}`); do not put `useTranslation` on every cell. Host is the Create or Edit icon-button (`budget.iconPicker.open`). `AddAccountButton` is Plus only (`onClick`). Pager swipe does not start when `event.target.closest('button')` — do not `stopPropagation` on Add. Wrap Create + picker in `Modal.Stack` (`stackId`). Glyph contrast: `accountIconGlyphColor` — black on `ACCOUNT_DARK_INK_FILLS` (white / lime / yellow, same tokens as `ACCOUNT_COLORS`), white otherwise. Do not add `accountFillInkColor`. CSS `--account-icon-glyph-color` on the badge, not `--account-icon-color`.
- Create account: one `CreateAccountModal` on `Budget` (not inside Add — the carousel mounts prev/current/next). Always mounted; visibility is Mantine `opened={create.opened}`. `Modal.Stack` may keep a closed dialog in the DOM (`opacity: 0`) — that is intended, do not unmount to “fix” it. Form queries use `enabled: opened` and `opened && showMoney`. `onAddAccount` is a void callback from `AccountBlock` through pager/viewport/grid; the pager hook still has no `AccountType`. Visibility is `createAccountVisibility(type, isDebt)` → `{ showKind, showMoney }` (exhaustive switch, not a field-slot list). Layout is 2D: icon+name, then money row (balance+currency), color outside the tinted block. Income: name, icon, color. Current: money row. Expense: kind; Debt also money row. Save: `createBudgetAccount` returns `{ ok: true } | { ok: false; reason: 'name' | 'failed' }` (same tagged result as login, not `Error.message`). Body via `toAccountStoreBody` (revenue / asset+`defaultAsset` / expense / liability+debt defaults) → `storeAccount` (no `throwOnError`) → `Promise.allSettled` of appearance + order `[...ids.filter(id !== newId), newId]` → `invalidateQueries` on prefix `BUDGET_ACCOUNTS_QUERY_KEY` only (do not also `refetchQueries`). Hook `switch`es on `reason`. `orderedIds` from Budget cache; opening date = `defaultTransactionDate({ month, today: todayIso() })`. Prefs failure after a successful store still closes. Persist `form.currency` (no `|| primary`). One session object `{ opened, type, id }`; remount with `key={id}` on each Add. When primary arrives and `currency` is still empty, write `primary.code` into the form; Select reads only `form.values.currency`. `fetchCurrencies` in `src/helpers/currency/` (`listCurrency` + `collectFireflyPages`, skip empty `code`; keep disabled currencies — Firefly ships the catalog with most `enabled: false` until used). Query key `CURRENCIES_QUERY_KEY` (`['currency', 'list']`), page limit `CURRENCIES_PAGE_LIMIT` 50 (do not reuse `EXCHANGE_RATES_PAGE_LIMIT` by name). Closed color set `ACCOUNT_COLORS` in `constants/appearance.ts` (includes `DEFAULT_ACCOUNT_COLOR`, `#FFFFFF`, `#000000`). Chromatic swatches are Mantine `DEFAULT_THEME` shade 6 — the same filled colors as the Button configurator. Glyphs and tinted-block labels share `accountIconGlyphColor` (black on `ACCOUNT_DARK_INK_FILLS`, white otherwise). ColorPicker `withPicker={false}` (Mantine 9 has no `swatchesOnly`). White/black swatches get an inset border so they read on the dark modal.
- Budget paging: one `AccountBlockPager` for Income, Current, and Expense (no third markup, no Embla/Mantine Carousel). Layout per block is `ACCOUNT_BLOCK_PAGER` (`fillHeight`, CSS `minHeight`, `minCardHeightPx`) spread into the pager — the hook does not know `AccountType` or Expense. `fillHeight` means stretch the viewport to measure leftover height and use `rowCount`; without it rows stay 1 (US-011). Expense rows are compact at card min-height (`grid-template-rows: auto`); leftover height is not distributed with `1fr`. No visible Income/Current/Expense headings; `aria-label` on the section. `useElementSize` on the viewport reads width and height. `useMediaQuery` with `961px`, not Mantine `md`. Paging math in `helpers/accountBlockPaging.ts`: `pageCount`, `slicePage`, `columnCount`, `rowCount` (height `<= 0` → 1 row, default gap `ACCOUNT_GRID_ROW_GAP_PX` 0), `nextPageIndex` (wrap last→0), `prevPageIndex` (wrap 0→last). Column gap stays `--mantine-spacing-xs` / `ACCOUNT_GRID_GAP_PX` (10); row gap is 0 — card padding (`--mantine-spacing-xs`) already separates row content. Item count is `accounts.length + 1` (Add last). `useAccountBlockPager` returns `columns`, `pageSize`, `totalPages`, `pageIndex`, `next`/`prev`/`goToPage` (derived clamp). Viewport slices by `pageSize` and loops by `totalPages` — do not recompute `columns * rows` there. Carousel: `AccountBlockViewport` (`usePageSwipe`, `pageSwipe.ts`), three slides (`prev | current | next`). Loop when `totalPages > 1`; rubber-band only on one page. Swipe tokens (`PAGE_SWIPE_*`) in `constants/layout.ts`; `PageSwipeDirection` in `types/pageSwipeDirection.ts`. Mobile `<961px` is 4 columns; unmeasured width (`<= 0`) stays 4. Arrows only desktop and `totalPages > 1`. Dots always. `AccountPageItem` in `types/accountPageItem.ts`; `toAccountPageItems` in `helpers/`. `useAccountBlockPager` and `usePageSwipe` live in `hooks/`; `pageSwipe.ts` in `helpers/`. `useBudgetAccounts` unchanged. US-027 can turn off swipe in the viewport; US-028 can keep a card in-hand at the edge without touching Query hooks.
- Account details: one `AccountDetailsModal` on `Budget`. Session is a discriminant: `{ opened: false; account: BudgetAccount | null } | { opened: true; account: BudgetAccount }`. Close sets `opened: false` and keeps `account` so the fade-out still shows the last header and transaction list. Pass `{...details}` into the modal so TypeScript keeps opened/account together. Do not use `createAccountVisibility` here — that helper is for Create (`showKind` / `showMoney`). Details header is `accountDetailsHeader` → `{ showKind, money: 'none' | 'balance' | 'debt' }`. Current money is balance+currency (`budget.accountDetails.balance`); Expense kind is text not `ExpenseKindControl`; Debt money is labeled debt/paid (`budget.accountDetails.debtAmount` / `paidAmount`), ink color of the header, not card red/green. Cards stay `div` with `role="button"` / `tabIndex={0}` / Enter+Space — not `<button>`, or pager swipe never starts (`closest('button')`). `onSelectAccount` goes Budget → block → pager → viewport `gridForPage` → grid → `AccountItem`. Pencil opens Edit (`onEdit` Budget → Details → Body → Header). Delete opens a local confirm in Details (`useDisclosure`, sibling `Modal` like the picker in Edit) — not a Budget session. Hide is the same pattern (`AccountHideConfirmModal`, no Budget session). `onClickCapture` already swallows click after a swipe. Prev/next carousel slides are off-screen (`inert`); interact with the current slide. Add still opens Create.
- Account transactions: `listTransactionByAccount` with `path.id` and `{ page, limit }` only — no `start`/`end`/`type`, so the list is all history, not the Budget month. Page limit `ACCOUNT_TRANSACTIONS_PAGE_LIMIT` 50 (do not reuse `ACCOUNTS_PAGE_LIMIT` by name). Query prefix `ACCOUNT_TRANSACTIONS_QUERY_KEY` is `['budget', 'accountTransactions']`; live key `[...prefix, accountId]`. Do not nest under `['budget', 'accounts']` or account invalidation will refetch transaction lists. Hook `useAccountTransactions(accountId, enabled)` with `enabled: opened`. No `placeholderData`. Mapper flattens every split; skip missing date/identity/amount; card key is `journalId` or `${groupId}:${index}`. Calendar day is the `YYYY-MM-DD` prefix of Firefly's ISO timestamp (not local dayjs). Groups desc by date, items desc by `dateTime`. Client filter is case-insensitive `includes` on description, from/to, currency code/symbol, amount, type, tags; empty query returns all. Same empty copy for no rows and no search hits: `budget.accountDetails.noTransactions`. Transaction cards are not clickable (US-029). Amount via `formatAccountAmount` — no History red/green dual currency. Search state remounts with `key={account.id}`. React files do not import dayjs. Edit transaction is US-029; infinite History scroll is US-030.
- Edit account: Budget mounts `Modal.Stack` (Details → Edit → picker) while Details is open or `edit.account` is set. Edit itself still mounts only when `edit.account` is set. Create stays in its own stack. Closed Details stays standalone — a closed stack overlay still captures clicks. Do not nest a second stack inside Edit. Do not add `locked` on Details or `zIndex` on the picker. Enter the stack on open Details so pencil does not remount Details (search / list UI). Toggle Edit with `opened`; keep `account` until Details closes so Mantine can `removeModal`. Closing Details clears `edit.account` and unmounts the stack. Form chrome is `AccountFormLayout` (tinted block, name/icon, money slot, color, actions); CSS tokens `--account-form-color` / `--account-form-ink` (also `AccountIconButton` / `AccountMoneyFields`). Create and Edit stay separate sessions. `showBalance` is `account.type === ACCOUNT_TYPE.CURRENT` — do not reuse `createAccountVisibility`. Name via `validateAccountName`. PUT `updateAccount` + `toAccountUpdateBody`: trimmed `name`; Current also `opening_balance` and `opening_balance_date` (pass `todayIso()` into the orchestrator). Appearance `.catch`; **do not** `writeAccountOrder`. Discard is `form.reset()`. Save invalidates `BUDGET_ACCOUNTS_QUERY_KEY`. Current also invalidates `[...ACCOUNT_TRANSACTIONS_QUERY_KEY, account.id]` — Details stays open and `opening_balance` can change the list. Income/Expense do not. Hide uses PUT `updateAccount` `{ name, active: false }`, not `updateBudgetAccount`.
- Delete account: confirm belongs to Details, not Budget — local `useDisclosure` and a sibling `Modal` in the Details tree (same as Edit's picker). No `DeleteAccountSession`, no `onDelete` on Budget. Stack stays `details.opened || edit.account`. Cancel / overlay / Escape close only confirm. Success invalidates `BUDGET_ACCOUNTS_QUERY_KEY` (the card) and `BUDGET_INSIGHTS_QUERY_KEY` (Income/Expenses in the bar). Do not invalidate that account's transactions — Details closes. Success is `response.ok` (`ok` includes 204). 204 is `void` — do not treat missing `data` as failure. Result is `{ ok: true } | { ok: false }` — one failure, no `reason` / `FAILED` constant / `switch`. Do not write appearance or order. Submit/error live in `AccountDeleteConfirmModal`; no delete hook. Hide is `hideBudgetAccount(id, name)` → PUT `{ name, active: false }`; success is `response.ok` (200 with body — do not require `data`). Do not reuse `updateBudgetAccount` / `toAccountUpdateBody`. Invalidate accounts only — hide does not change transactions, so Income/Expenses insights stay. Balance follows Current from the accounts cache. Do not invalidate account transactions (Details closes). Hide button is `variant="default"`, not red (reversible in Firefly). i18n `budget.accountDetails.hideConfirm` / `hideFailed`; Hide label is existing `budget.accountDetails.hide`. Hide confirm has no title so a11y snapshot may omit it — read dialog text via CDP. 204 fixture `data` is `void`. Clear error on close, not in `useEffect`. Pager: click the on-screen card, not an `inert` slide.
