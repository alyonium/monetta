# US-028: переносить счёт на другую страницу во время драга

**История:** [US-028](current-task/feature.json) — priority 28, `passes: true`. Figma нет (`designReference: []`).

Свайп пальцем по-прежнему выключен, пока `DndContext.active` задан. Листание у края идёт мгновенным `onPrev` / `onNext`, не `slidePrev` / `slideNext`.

## Поведение

- В Edit `useAccountDragPageEdge` смотрит `pointermove` на документе. Курсор внутри блока по вертикали и в полосе `ACCOUNT_PAGE_EDGE_PX` (28px), включая точку за границей блока, вооружает край. Каждые `ACCOUNT_PAGE_EDGE_HOLD_MS` (450ms) на том же крае страница меняется. Уход из полосы таймер снимает. Так карточку можно донести до любой следующей или предыдущей страницы блока.
- Счёт в руке — `activeAccount` с `onDragStart`. После смены страницы исходная карточка размонтируется, и `event.active.data` уже нельзя читать.
- `onDragOver` пишет `overAccount` только в Edit и только для другого счёта того же блока. Дыра между карточками цель не стирает. Курсор над самой карточкой в руке тоже не стирает: её клетка остаётся droppable, но в защёлку не попадает. В режиме записи `dragover` это состояние не трогает.
- Превью и `reorderBlock` на отпускании берут одну и ту же пару `activeAccount` / `overAccount`. `previewAccountPage` двигает полный список блока и режет страницу; если срез не изменился, превью нет.
- Сдвиг — `translate` на измеряемой карточке. dnd-kit снимает transform только с этого узла, поэтому зона попадания остаётся в исходной клетке. Величина сдвига — разность `cellPosition`. Вторая копия карточки есть только у счёта, которого на странице ещё нет: она заполняет клетку назначения и приезжает из-за края. `SlotTarget`, `crossPageShift` и копия всей страницы не используются.
- `reorderBlock` по-прежнему возвращает `null` при разных типах, совпавшем id или отсутствующем id. Запись порядка — `persistBlockOrder`.
